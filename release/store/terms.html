SENTINEL TERMS OF USE
Version 4 — 9 November 2026

Use Sentinel only with computers you own or have explicit authorisation to
access. You are responsible for the SSH account and permissions you choose,
verifying the host fingerprint independently, and reviewing helper installation
and key authorisation with the PC administrator.

Monitoring and terminal access are separate. The monitoring key must be
restricted to the documented read-only helper. Optional terminal authorisation
allows commands with the chosen account's normal permissions. Commands may
modify/delete files, interrupt work or contact other services. Do not grant
unnecessary privileges or share private key material.

This release supports compatible Linux PCs over an existing reachable SSH route.
It requires a compatible Python helper on the PC. Not all sensors or accounts
will be visible. It provides foreground monitoring and a basic line-oriented SSH terminal, not
remote desktop or Kitty mirroring. Selected processes can be watched, but their
disappearance does not prove success. Optional PC runner results verify only the
direct command's exit; detached children and backup contents are not verified.
Expected-success rules do not schedule work. An explicitly started background
session polls for task outcomes and optional sustained health warnings with an
ongoing notification and Stop control. Android/network delays, app/process stop
and phone restart can interrupt it; delivery is not guaranteed. Quiet hours,
severity, mute and cooldown controls can suppress or defer notifications.

Shutdown and reboot use existing Terminal SSH access, a held arming control and
the PC account's administrator/sudo password entered fresh for each action.
No fingerprint or phone PIN is required for power actions. Existing sudo rights
and systemd are required; blocking inhibitors are respected. These actions affect
every PC user and interrupt running work.

Readings can be missing, delayed or stale. An unreachable PC is not necessarily
powered off. Check important work independently. Leaving/backgrounding the
terminal disconnects it and can interrupt jobs. Sentinel is not a safety-critical
monitoring, backup or data-recovery system.

Sentinel is provided as available, without a guarantee of uninterrupted service,
complete hardware compatibility or error-free readings. Nothing in these terms
excludes statutory consumer rights or liabilities that applicable law does not
allow to be excluded. You can stop using the app at any time and erase its local
data. Remove its public keys on the PC to revoke access fully.

Selected process watches/history and macro templates are retained encrypted on
the phone. Optional runner metadata and expected-success rules remain on the PC;
erasing phone data does not erase those records. Do not save secrets in macro
templates. Review commands before running them.

See the Privacy policy for data handling and deletion. Open-source components
remain subject to their respective licences, included in Open-source licences.
Publisher/support details will be supplied in the public store listing before
release. These terms do not authorise Sentinel to collect analytics or send your
PC data to its developer.

Device verification and power actions
Sentinel requires phone fingerprint or screen-lock verification only to reveal
saved connection settings or terminal details. Opening the app, monitoring and
shutdown do not require phone verification. Shutdown requires the PC sudo
password entered fresh for each request. Android handles phone verification;
Sentinel never receives your phone PIN or biometric template. A secure phone
screen lock is required to reveal saved connection settings and terminal details.
USE_BIOMETRIC enables the system verification prompt. Screenshots and recent-app
previews of the app are blocked. Host/port/login profiles are encrypted in private
phone storage with an Android Keystore AES-GCM key and remembered separately.

Shutdown and reboot use the existing Terminal SSH key and your PC account's existing sudo
permissions. Each request asks for the PC administrator password in a masked field.
This is the PC password, not your phone PIN. It is held only for that request, sent
only to the fingerprint-verified SSH host when its sudo prompt is received, and
never saved in profiles, command text, logs, history, analytics or a developer
service. Raw authentication output is not displayed. Your PC/PAM may independently
record authentication attempts under its existing logging policy.

The app first verifies PC administrator authentication without a power command.
Only an explicitly armed power action proceeds to a fixed systemctl command,
respecting blocking inhibitors and existing sudo rights. The separate verification
check cannot request shutdown or reboot. Password retries and shutdown retries are not
automatic. All PC users and running work can be affected; a lost reply is reported
as uncertain. No new PC helper, software download, sudoers/polkit rule, SSH key
authorisation, service or network change is made for shutdown. Existing monitoring
still uses its previously documented helper. SSH passwords are not stored.
